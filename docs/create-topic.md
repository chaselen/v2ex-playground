# 创作新主题

## 功能范围

创作面板可从主视图“我的”页面昵称右侧的编辑按钮打开，也可从节点页的“创建新主题”按钮打开。节点页入口会预选当前节点；创作面板已打开时会保留标题、正文和语法，只切换节点。主视图入口内部复用 `v2ex.createTopic` 命令，支持：

- 标题、正文、语法和节点选择
- V2EX 原生格式与 Markdown
- 语法切换右侧的语法帮助和节点选择旁的节点使用说明，分别打开插件内 `/help/markdown` 与 `/help/node` 帮助页
- 与 V2EX 网页一致的主题正文预览
- 选择、粘贴和拖放图片上传
- 按 V2EX 用户名隔离的本地草稿
- 发布成功后打开新主题的现有话题面板

## `/write` 发布契约

扩展不在打开创作面板时请求或解析 `/write` 页面。标题上限 120、正文上限 20000、默认 Markdown 作为与当前网页版一致的稳定契约，由扩展侧常量统一维护。

Webview 打开后直接使用这些静态约束渲染完整表单，不展示整页加载态；登录校验、节点加载和草稿恢复完成前暂时禁用编辑与发布，避免恢复草稿时覆盖用户刚输入的内容。

发布时使用 `POST /write`，当前字段为：

| 字段        | 含义                         |
| ----------- | ---------------------------- |
| `title`     | 主题标题                     |
| `syntax`    | `default` 或 `markdown`      |
| `content`   | 主题正文，允许为空           |
| `node_name` | 节点 name                    |
| `once`      | 发布前通过 `/poll_once` 获取 |

Webview 和领域层使用同一组长度常量进行提交前校验。

## 节点来源

节点选择复用 `V2exClient.getAllNodes()` 和 `src/features/nodeQuickPick.ts`，数据来自 V2EX `/api/nodes/all.json`。发帖选择器按 `topics` 对应的主题总数降序排列，并在标签中显示主题数；当前节点在标题前显示 `$(check)` 标识。添加自定义节点继续显示收藏人数和原接口顺序。

`NodeService` 在进程内缓存全量节点。Webview 通过 RPC 打开 VS Code QuickPick；提交时扩展侧再次确认 `node_name` 存在于最新节点列表，避免发送过期或伪造的节点值。

创作页与移动主题弹窗的节点选择按钮复用 `components/NodeSelectButton.tsx`，统一头像、标题、name、箭头以及组件内的交互样式，发布区域与正文卡片使用相同页面底色，避免浅灰区块叠加输入框底色造成不协调。选择器可用时使用输入框背景和前景，悬停及键盘焦点使用焦点边框，禁用时保留公共按钮的禁用样式。

节点选中后使用 `getV2exNodeAvatarUrl()` 生成 `img.fuyou.tech/v2ex/node/{node}` 代理图标，在发布区展示并随草稿恢复。

## 预览与发布

主题正文复用话题页的 `ReplyComposer` 编辑、预览和图片上传能力。组件在创作场景使用受控正文，并由创作页注入语法对应的主题预览请求；回复场景继续固定使用 V2EX 原生格式，不提供 Markdown 选项。

主题正文预览请求 `POST /preview/{syntax}`，表单同时携带：

- `text=<正文>`
- `topic_content=1`

`topic_content=1` 是主题预览与回复预览的差异，必须保留。

发布请求使用 `POST /write`。成功后 V2EX 重定向到 `/t/{id}`，领域层从最终响应地址提取主题 ID。Session 统一使用重定向地址的 pathname 识别 `/signin` 和 `/restricted`：前者清理失效登录并提示创作需要登录，后者返回账号受限错误；停留在 `/write` 时由话题服务解析页面错误提示。领域服务不重复执行失效清理。

## 草稿

草稿保存在扩展 `globalState` 的 `v2ex.createTopicDrafts` 中，以规范化后的 V2EX 用户名为键。草稿包含标题、正文、语法和已选节点，不包含 Cookie 或 `once`。

Webview 在编辑停止 500 ms 后保存草稿。重新打开创作面板时恢复当前账号草稿；如果保存的节点不在最新全量节点列表中，则只清除节点选择，保留标题和正文。主题发布成功后清除当前账号草稿。

## 边界条件

- 正文可以为空，标题和节点不能为空
- 默认语法固定为 Markdown
- `once` 只在实际发布前获取，不写入状态或草稿
- 发布是不可逆的远程写操作，Webview 必须在提交前显示确认浮层
- 作者在话题面板中可使用修改、移动节点和 APPEND，入口以当前服务端页面提供的链接为准

## 发布后的作者管理

[官方规则](https://www.v2ex.com/t/164415)：创建后 600 秒（10 分钟）内允许修改和移动，1800 秒（30 分钟）后允许添加 APPEND。当前中文 APPEND 页面还注明每个主题最多 3 条附言，每千字收费 20 铜币。扩展展示这些规则，但不使用客户端时钟推算权限。

话题解析器只识别主题头部元信息中当前主题的 `/edit/topic/{id}`、`/move/topic/{id}`、`/append/topic/{id}` 相对链接。作者操作只在主话题面板展示；站内预览不提供管理入口。打开表单和提交时都重新读取话题页面，服务端未提供对应入口时拒绝操作。

作者管理使用固定的领域类型、RPC 参数和 UI 表单。初始化时检查服务端权限，仅编辑操作额外请求编辑页，提取原始标题、正文和当前语法；不能从主题页已渲染的 HTML 反推正文。移动的当前节点直接使用话题详情，APPEND 从空正文开始。

提交契约如下：

| 操作 | 路径                      | 请求字段                     |
| ---- | ------------------------- | ---------------------------- |
| 编辑 | `POST /edit/topic/{id}`   | `title`、`content`、`syntax` |
| 移动 | `POST /move/topic/{id}`   | `destination`，值为节点 name |
| 附言 | `POST /append/topic/{id}` | `content`、`syntax`、`once`  |

编辑与附言的 `syntax` 都使用 `0`（V2EX 原生格式）或 `1`（Markdown），由领域层将业务类型 `default/markdown` 映射成请求值，与 `/write` 的枚举格式不同。编辑和移动的实际表单没有 `once`；仅附言在提交前复用 `AuthService.getOnce()` 通过 `/poll_once` 获取令牌，不解析或缓存隐藏字段。编辑标题和附言正文不能为空，编辑正文允许为空，移动必须指定目标节点；服务端错误仍由响应页面提取。

APPEND 按钮和对话框标题统一为“添加附言”，正文省略重复字段标签，语法使用编辑器工具栏中的分段切换，与创作页一致。弹窗立即展示空编辑器，不使用骨架屏；后台读取话题详情并校验权限，完成前禁止提交但允许输入、预览和选择语法。后台权限响应不回填表单，不覆盖已输入的正文和已选语法；校验失败时保留编辑器和输入并展示错误。提交时仍重新检查权限并获取附言令牌。操作说明放在表单底部、操作按钮上方，以分割线和辅助文字样式展示；附言采用原站的必要性、最多 3 条和每千字 20 铜币说明。编辑器不叠加回复场景的顶部外边距。

正文编辑复用 `ReplyComposer` 的预览和上传，主题和附言预览均携带 `topic_content=1`；预览直接使用业务语法类型，提交时统一映射为服务端数字枚举。移动弹窗分别显示当前所在节点和目标节点。目标节点使用与创作页一致的图标、标题、name 和下拉箭头选择按钮，点击打开全量节点 QuickPick，标记当前选中的目标节点；取消选择保留原目标，切换目标不会改变当前所在节点的展示。编辑、移动和添加附言均直接提交，不再弹出确认浮层；附言的条数和费用说明始终显示在弹窗底部。

成功必须重定向到当前 `/t/{id}`，停留在表单页时展示服务端错误。保存后刷新当前回复页、面板标题和最近浏览。若写入已成功但刷新失败，明确提示用户刷新核对，阻止在当前对话框重复提交；失败时保留输入内容。同一面板的作者管理提交串行执行。

管理能力的真实页面测试只读取公开主题和登录态可用表单，不发布、修改、移动或追加真实内容。
