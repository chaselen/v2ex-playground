# 官方回复关联与七种显示模式

契约来源：[V2EX 楼中楼说明](https://edge.v2ex.com/help/reply-threads)及 2026-11-16 登录状态下的真实 HTML。插件跟随话题响应 `.reply-threads-{style}` 的实际模式，刷新、重新打开或翻页时同步官网设置，不写回账户设置。缺失或未知标记按经典平铺处理，不额外请求设置页。

## 关联语义

官方通过提交表单的 `parent_id` 记录回复对象。手动输入 `@用户名`、`#楼层` 及功能上线前的回复不具有官方父回复关系。插件不根据正文推断关系；普通提及不能使回复自动嵌套。

点击回复按钮会选定目标并插入用户提及。仅输入提及时可重新选定目标；若追加后提及多个不同用户，则取消单一楼层关联，改为回复主题，并显示随正文编辑更新的“回复 N 人”，用户名去重不区分大小写。开始写正文后，再点击只追加提及并保留原目标。取消目标后改为回复主题，正文保留。草稿同时保存正文与目标，不因翻页丢失；主话题与预览回复框独立保存。提交仅在选定目标时携带 `parent_id`。

发表使用官网 AJAX 契约：`content`、最新 `once`、可选 `parent_id` 和 `return_to_page`，携带 JSON Accept 与 XMLHttpRequest 头。只在 `success: true` 时清空草稿；读取返回的 `reply_id` 和 `url` 中页码，加载后展开、定位并高亮新回复。已发表但加载失败仍返回成功结果并单独提示，避免重复提交。预览发表不驱动主面板翻页。

草稿以持久化版本关联一次提交。发表成功后直接清除该版本，不依赖原编辑器仍然挂载；重新打开的同版本编辑器也会同步清理。用户后续编辑产生新版本，旧提交成功不能清除它。主面板发表后的自动定位还须确认没有更新的翻页请求，不能仅比较当前已经显示的页码。

## 服务端布局差异

| 设置值 | 模式            | 结构与交互                                                                             |
| ------ | --------------- | -------------------------------------------------------------------------------------- |
| `off`  | 经典平铺        | 楼层顺序；响应不展示父回复关联                                                         |
| `a`    | 引用条          | 楼层顺序；`.reply-strip` 指向父回复                                                    |
| `b`    | 角标 + 悬浮预览 | 楼层顺序；`.reply-chip` 和 `.reply-answered` 提供双向入口；跨页预览可能在 template 中  |
| `c`    | 楼中楼          | 同一讨论收进 `.reply-group`，真实子回复嵌入父回复 DOM；深层目标可通过 `.reply-to` 识别 |
| `d`    | 树形缩进        | 单元格保持平铺，按讨论重排；`data-depth` 表达层级，细线或回复数可折叠子树              |
| `f`    | 对话连线        | 楼层顺序；同页 `data-parent-id` 用于连线，跨页引用条用于跳转                           |
| `h`    | 引用楼层        | 楼层顺序；`.reply-quote` 完整引用父回复，`.reply-quote-up` 折叠更早上文                |

`parseReplies()` 收集全部真实回复，包括官方嵌套单元格，但排除用户正文和引用中的同名单元格。作者、头像、徽章、时间和正文仅从该回复自身读取，避免子回复和引用污染。数据按数字楼层排序，父回复保存为明确引用。服务端包装的 `.reply-at` 在解析时解包，展示端只在分组和树形模式下隐藏与明确父回复匹配的开头提及。

`ReplyList` 供话题页、站内预览与分享图共用：分组模式把后代按楼层顺序收在同一框内，树形模式保持父子分支顺序。树形引用跳转会展开目标的祖先，从长连线底部收起时把父回复带回可见区域；定位作用域限定在当前列表。对话连线按整段讨论使用最多五条轨道与六种颜色，拥挤时暂停下次出现最晚的讨论并以虚线续接；保留非连续父回复的跳转标记和跨页引用入口。支持悬停聚焦、点击连线区域或头像固定高亮，键盘可通过连线按钮操作。图片、折叠和容器尺寸变化后重新测量。

连线使用容器的布局坐标；弹窗入场缩放时，视口坐标必须还原缩放比例，不能依靠 ResizeObserver 在 transform 动画结束时再次通知。

引用楼层按服务端实际提供的上文链解析和展示，不附加固定层数截断；渲染保留回复编号的循环检测。官网说明和前端脚本未提供固定 20 层上限，已有真实 HTML 样本只有四层，不能据此断言服务端不存在其他上限。

## 分页、可见性与导出

跨页父回复保留服务端目标页码和预览，在当前页显示引用入口，不挂到同名用户或同一页其他回复。跳转加载目标页后定位对应回复。服务端未提供的隐藏、忽略或 Block 内容不额外请求补全。

角标模式保留官网 `.reply-answered` 的反向引用，包括跨页目标，并与当前页明确父回复生成的入口去重。同页引用使用本页正文预览；跨页仅在服务端提供正文时显示预览，否则保留跳转入口。

分享图跟随官网模式，不再提供独立的推断模式开关。树形子树与引用上文在导出时全部展开，悬浮预览保留静态角标。引用正文图片与普通正文使用同一缓存和内联替换链路。

## 验证

- `parsers/fixtures/replyThreads.json`：话题 1257325 的七种布局及部分第二页样本，仅保留回复区并移除 token 与操作脚本
- `parsers/replyThreads.test.ts`：七种模式无损、元信息隔离、父回复一致、跨页链接与恶意正文同名结构
- `tests/replyTree.test.ts`：只使用明确关系、异常目标与连线轨道
- `tests/replyTree.live.test.ts`：当前账号模式下的新旧话题和分页；只读，不切换官网设置
- `webview/theme.html`：七种模式、四种主题、窄布局、悬浮预览、折叠与引用跳转

上述默认回归不发表回复。VS Code / Cursor 的首次打开、重复打开和隐藏恢复仍需宿主手动回归。

`tests/replySubmission.live.test.ts` 默认跳过，仅同时提供 `V2EX_REPLY_TEST_TOPIC_ID`、`V2EX_REPLY_TEST_PARENT_ID` 和 Cookie 时发表一条回复，并在写入前校验节点为 `sandbox`。已发表后可提供 `V2EX_REPLY_TEST_EXISTING_REPLY_ID` 只重验读取结果，避免断言调整或网络重试造成重复写入。
