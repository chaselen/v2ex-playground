# 主题写操作接口契约

本文保留 V2EX 发布、编辑、移动、附言、首页推广和下沉的请求差异及权限边界。请求实现在 `src/v2ex/services/`，HTML 解析在 `src/v2ex/parsers/`；主题发布及作者管理的真实页面测试只读取页面与表单，不执行发布、编辑、移动或添加附言。

## 发布

`POST /write` 使用以下表单字段：

| 字段        | 值与约束                               |
| ----------- | -------------------------------------- |
| `title`     | 必填，最多 120 字符                    |
| `content`   | 允许为空，最多 20000 字符              |
| `syntax`    | `default` 或 `markdown`，默认 Markdown |
| `node_name` | 全量节点 API 中的节点 name             |
| `once`      | 提交前通过 `/poll_once` 获取           |

长度约束由扩展侧常量统一维护，不依赖打开面板时读取 `/write`。提交时重新确认节点存在于全量列表；发布前显示确认浮层。

成功必须重定向到 `/t/{id}`，从最终地址提取主题编号。停留在 `/write` 时解析页面错误；重定向到 `/signin` 或 `/restricted` 由 Session 统一处理登录失效或账号受限。

## 作者权限

[官方规则](https://www.v2ex.com/t/164415)说明：主题创建后 600 秒（10 分钟）内允许修改和移动，1800 秒（30 分钟）后允许添加附言。这些时间用于界面说明，实际权限仍以服务端提供的操作入口为准。

编辑、移动和附言入口以当前主题头部的 `/edit/topic/{id}`、`/move/topic/{id}`、`/append/topic/{id}` 链接为准。打开表单及提交前均重新读取主题页检查权限，不使用客户端时钟推算是否允许操作。内容操作与展示管理使用独立的权限和请求契约：内容操作使用编辑弹窗，展示管理在锚定浮层中选择操作，通过独立 Dialog 二次确认，放到首页的帮助链接直接打开官方说明，入口仅在完整话题面板展示；提交互斥与操作后刷新由面板统一处理。

编辑原文必须读取编辑页，不能从已渲染的主题 HTML 反推正文；移动的当前节点使用话题详情，附言从空正文开始。

### 编辑原文与 HTML 实体

编辑框原文以服务端编辑页的 textarea 值为准，不保证与提交前字符串逐字相同：服务端可能去除正文首尾空白并调整中英文间距。页面会将正文中的 HTML 标签和实体字面量再次转义，读取时只能解码一层；例如编辑框中的 `&lt;` 在 HTML 源码中是 `&amp;lt;`，不能继续还原成 `<`。CRLF / CR 按 HTML 输入规则规范为 LF，不对解析结果额外 trim。

`parsers/fixtures/topicContent.json` 保存了[沙盒样本 1249137](https://www.v2ex.com/t/1249137) 的 Markdown / Default 原始表单片段，使用 JSON 字符串保留源 HTML 中的 CR、LF、Tab 与行末空格。期望值与浏览器原生 textarea 值核对，覆盖实体、代码、字面结束标签和换行；快照不含账号导航或会话令牌。

编辑权限有时间限制，长期回归使用上述离线快照。需要重新验证真实编辑页时，可在沙盒创建原文与快照期望一致的主题，通过 `V2EX_EDIT_FIXTURE_TOPIC_ID` 指定仍可编辑的主题运行 `client.topics.live.test.ts`；该测试只读取，不自动创建或修改主题。

## 编辑、移动与附言

| 操作 | 路径                      | 表单字段                     |
| ---- | ------------------------- | ---------------------------- |
| 编辑 | `POST /edit/topic/{id}`   | `title`、`content`、`syntax` |
| 移动 | `POST /move/topic/{id}`   | `destination`，值为节点 name |
| 附言 | `POST /append/topic/{id}` | `content`、`syntax`、`once`  |

编辑和附言的 `syntax` 使用 `0`（原生格式）或 `1`（Markdown），与 `/write` 的字符串枚举不同。编辑、移动的表单没有 `once`；附言在提交前通过 `/poll_once` 获取，不缓存令牌。

编辑标题和附言正文不能为空，编辑正文允许为空。成功必须重定向到当前 `/t/{id}`，停留在表单页时解析服务端错误。同一面板串行提交；写入成功但刷新失败时提示刷新核对，并阻止当前表单重复提交。

## 正文预览

主题与附言均使用 `POST /preview/{syntax}`，携带 `text=<正文>` 和 `topic_content=1`。回复预览不携带主题标记，固定使用原生格式。预览与提交使用的语法枚举需分别映射，HTML 输出约束见 [内容预览 HTML 契约](reply-preview-html.md)。

## 放到首页与下沉

作者管理栏的 `onclick` 提供确认文案与携带 `once` 的 GET 跳转：放到首页为 `/t/{id}/boost?once=...`，下沉为 `/fade/topic/{id}?once=...`。只在 `#Main` 直属管理栏按“放到首页”“下沉”链接文字识别操作（允许末尾箭头），再从完整字符串中校验对应操作路径与主题编号，只返回不含查询参数的操作路径，不解析或校验页面中的 `once`。确认说明按操作文字及费用或时长读取，不依赖 `if`、`confirm` 或跳转函数的写法。不执行脚本，不接受正文入口或外站地址；令牌不传往 Webview。

实际提交前通过 `session.getOnce()` 请求 `/poll_once`，将最新令牌附加到操作路径；不缓存或回退使用旧令牌，获取失败时停止提交。

资格要求和按主题创建年份递增的费用规则见[官方 Boost 说明](https://www.v2ex.com/help/currency?#boost)。管理浮层只为放到首页提供帮助链接，在帮助面板定位到 `boost` 章节；实际费用仍以当前确认文案为准。打开确认框时读取最新说明，提交前重新获取入口；若费用或说明变化则停止提交并要求重新确认。下沉文案为 10 天；成功提示示例为“主题 1248973 已经被下沉 10 天”，按“已被下沉”或“已经被下沉”关键词识别，不绑定编号和时长。请求携带当前主题地址作为 `Referer`；无 `Referer` 时源站可能回到首页并显示成功通知，不能仅凭最终地址判定失败。放到首页仅核对入口和离线请求契约，不做真实推广测试。
