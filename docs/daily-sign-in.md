# 每日签到的状态与边界

签到编排在 `src/features/dailySignIn.ts`，请求在 `src/v2ex/services/account.ts`，余额解析在 `src/v2ex/parsers/balance.ts`。

## 页面状态与到账记录

`/mission/daily` 决定当前任务是否可领取，`/balance?p=N` 决定奖励是否实际到账。页面显示已领取不代表北京时间今日的任务已经完成：任务刷新前可能仍属于上一任务日，不能只凭本地日期生成状态。

奖励任务日优先从流水描述 `YYYYMMDD 的每日登录奖励` 提取，缺失时才回退到流水时间的日历日。所有今日、昨日和小时比较使用北京时间，不使用宿主系统时区。

余额流水只匹配类型为「每日登录奖励」、方向为正、数额大于零的记录，不能混用每日活跃度奖励或连续登录奖励。最多扫描前五页；找不到时奖励数和任务日均可能缺失，页面的已领取状态仍有效。余额按币种图片 alt 解析，不能按数字顺序映射，因为零值高位币种可能缺席。

## 领取成功的判据

领取前读取最新奖励，从签到页获取领取令牌后执行 redeem，再查询流水。只有最新奖励的任务日发生变化才确认为成功；页面原本已领取则返回重复领取结果。

同一自然日可能在任务刷新前补领上一任务日，刷新后再领新任务日。两条流水的墙钟日期甚至铜币数都可能相同，因此不能用它们判断是否新增奖励。领取后没有确认到新任务日流水时返回失败，即使远程领取可能已发生。

## 调度与缓存取舍

任务刷新通常约在北京时间八点，但调度不依赖固定刷新瞬间。自动签到按小时检查，并在登录和面板恢复可见等入口触发；页面已领取时不启动带 loading 的领取流程。

完成缓存绑定已验证用户名与任务日，仅接受北京时间今日或昨日。昨日任务已领取只能写昨日，不能使八点后的新任务被当作今日完成。

自动签到在北京时间 0:00–7:59 且昨日本地已完成时跳过网络请求，减少休眠、断网时的重试噪声；没有昨日缓存仍会查询并尝试补领。八点起恢复检查，任务实际刷新后最多可能延迟约一小时领取。

缓存只是减少请求的依据，缺少奖励数时会重新查询补齐。任务刷新时间若变化，凌晨安静窗口可能延迟发现新任务。

## 账号与并发边界

同一用户名的手动、自动签到共用进行中的任务，不同用户名不能复用。写缓存、继续重试、更新状态或提示前再次比较用户名，防止旧账号结果影响新账号。

领域层仅在 redeem 前后比较 A2 快照；补充两步验证 A2O 不代表切号。快照变化不能撤回已发出的请求，只能阻止后续成功确认；状态查询和余额翻页没有完整请求链隔离。同一用户名换入另一份 A2 时，功能层仍视为同一账号。

自动失败允许有限重试，手动失败不自动重试。重复领取不发成功通知；自动失败仅记日志，避免后台调度反复打扰。

## Webview 状态

首次加载主动读取状态，事件负责后续同步，不能依赖一次初始化推送。loading 事件中的 signedIn 只反映本地今日缓存，不能覆盖已有的已签到状态；任务最终结果再更新签到状态和奖励。奖励缺失时不展示「获得 0 铜币」。

验证重点包括凌晨补领与刷新后领取、重复领取但奖励缺失、redeem 前后切号、两步验证、同账号任务复用及初始化与 loading 事件交错。
